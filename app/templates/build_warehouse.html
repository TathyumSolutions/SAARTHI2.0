2. Data Model

Every discovered table, with relationships drawn from the data sources' own metadata wherever possible - a declared foreign key straight from the source database's schema first, then a join your Metamind router already inferred from actual sample-value overlap (not just naming), and only as a last resort a plain naming-convention guess for tables with no such metadata (spreadsheets). This is the map Table-Level Mapping below draws its join-key suggestions from once you combine two related tables - review it, it isn't something you need to fix by hand.

3. Table-Level Mapping (Joins)

Mapping isn't always 1:1 - a target table can be built by joining more than one source table. Drag a source table from the left onto a target table on the right to combine them (a join); drag it back out (✕ on its chip) to split it out again. Target table names are editable. Once a target table has more than one source, set the join type and at least one join key below it - a join key detected in the Data Model above is pre-filled automatically when possible. Column-level transformations (Configure Mapping, in the Table Selection step below) are always based on whatever is saved here.

6. Generate, Upload, or Run

"Generate Script" downloads a standalone .py file for external/cron use (database-sourced target tables only, joins included). Need a manual change? Edit the downloaded file, then "Upload Script" to load your edited copy back in before executing. "Run Now" executes the same job immediately inside the app - it supports spreadsheet-sourced and joined target tables too, plus any saved column mapping/transforms.
